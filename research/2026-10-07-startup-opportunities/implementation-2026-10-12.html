Implemented behavior

  • Pactrun refuses the unsupported Responses API path. Covered calls reserve estimated spend atomically; streams, failures, cancellation and uncertain usage settle conservatively. Async SDK subclasses remain enforced.
  • Approval v2 authenticates timestamps, nonces, selected arguments and host-owned context. SQLite consumes grants/quorums atomically across sessions and restarts. Monitor replay simulates consumption without touching live grants.
  • The cassette bridge normalizes fresh/cache tokens and retains observed result provenance, IDs and turns. Missing cost and ambiguous or duplicate results are refused.
  • The synthetic refund application enforces ownership, state and bound approval; persists action state; uses provider idempotency; and reconciles unknown results. Tests execute changed application code against a recorded SDK reply.
  • Gemini uses google-genai. Playback covers current and legacy httpx/httpx2 transport paths. Contributor tasks and a one-workflow customer pilot scope are documented.

Migration and practical limits

Reissue approval tokens: pre-v2 envelopes are rejected. Durable replay protection requires a signing secret and a persistent host-owned store. Grant consumption does not prove a named human approved or guarantee exactly-once execution of a real remote payment.

Budget reservations cover one wrapper and remain estimates. The refund application is a reference simulator to adapt to actual customer endpoints. Existing baseline research remains historical; current regression tests verify the fixes. No real payments, paid model calls, customer outreach or revenue validation occurred.
